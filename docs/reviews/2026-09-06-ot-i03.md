Implemented contract:

- The route rejects cross-origin requests before reading the body. Multipart
  upload requires the exact tenant-bound `brand.proposal.upload` permission.
  Upload does not review or apply the proposal.
- The request stream is capped at 278,528 bytes before multipart parsing. One
  `.md` file may contain at most 262,144 bytes and must use `text/markdown` or
  `text/plain`. UTF-8 decoding is strict. The existing parser keeps its 64-key
  ceiling and rejects the whole upload when any recognized key is invalid.
- SHA-256 is computed over the original bytes. The transaction records the
  registered parser version, per-value upload attribution, a synthetic
  `upload:<digest>` request and one canonical upload audit event. Identical bytes
  are a no-op. A different upload supersedes only an existing draft.
- GFinal review found that the original route passed upload authority but not
  the distinct supersede decision into that transaction. The correction derives
  both from the current tenant session. Without supersede authority, a different
  upload receives `403`; the transaction keeps the current draft and adds no
  proposal or audit event.
- The page read model caps the result at 100 rows, keeps every join tenant-bound
  and returns typed upload or HTTPS provenance without document content. Upload
  values must agree on actor and timestamp; malformed or conflicting attribution
  fails closed.
